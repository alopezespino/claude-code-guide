# Mathematica and VS Code: a household time-allocation example

A minimal working example of how to split Wolfram Language work between plain-text
package files (edited in VS Code, by you or by Claude, and tested from the terminal)
and a small Mathematica notebook (for interactive exploration and figures).

## The model

A couple decides how to split time between market work and home production. The
husband (spouse 1) earns wage `w1` and the wife (spouse 2) earns `w2`. Each has one
unit of time; spouse `i` works `hi` hours in the market and `1 - hi` at home.

```
consumption        c = w1 h1 + w2 h2
wife's share       s = w2 h2 / c
household utility  U = Log[c] + gamma theta Log[1 - h1]
                         + gamma (1 - theta) Log[1 - h2]
                         - kappa Max[0, s - 1/2]^2
```

- `gamma` is the weight on the home good, `theta` the husband's weight in home
  production (`1/2` is symmetric).
- `kappa` is a gender-role bias: a utility cost that is zero while the wife earns at
  most half of market income and grows with her excess share.

Without bias (`kappa = 0`) the problem has a closed form: the spouse with the higher
relative wage works more in the market, and when `w2/w1` is high enough the husband
specializes at home. With bias (`kappa = 2`), once the wife's wage passes the
husband's, her market hours stay close to his instead of rising, and his stay close to
hers instead of falling; her share of income then grows only through her higher wage
(see `results/market_hours.png`).

The application is inspired by GeeYoung Oh, "Allocating Time As A Couple: Effects of
Relative Wages and Gender Role Bias"
([research page](https://sites.google.com/view/geeyoungoh/research)). The model here
is a simplified teaching version written for this example, not her model.

## Layout

```
mathematica-household/
├── src/Household.wl              # the model: package with usage messages
├── tests/HouseholdTests.wlt      # VerificationTest checks
├── tests/run.wls                 # runs the tests, exits 1 on any failure
├── scripts/sweep.wls             # parameter sweep, writes results/
├── notebooks/build_notebook.wls  # generates notebooks/Household.nb
├── notebooks/Household.nb        # small notebook: loads src/, Manipulate, plot
└── results/                      # sweep output (only the figure is tracked)
```

## What goes where

- **`.wl`, `.wls`, `.wlt` files** hold everything that must be right: the model, the
  solver, the tests, the batch runs. They are plain text, so git diffs are readable,
  and Claude can edit them and run them from the terminal with `wolframscript`.
- **The notebook** only loads the package and explores it: a `Manipulate`, a plot. It
  holds no model code. If the notebook and the package disagree, the package wins.
- **Claude does not hand-edit `.nb` files.** A notebook is a nested box expression
  with cached output; edits are hard to review and easy to corrupt. Here the notebook
  is generated by `notebooks/build_notebook.wls`, which syntax-checks every input cell
  and saves the notebook without outputs. To change the notebook, change that script.

## Running it from the VS Code terminal

Run these from this folder (`examples/mathematica-household/`). They need
`wolframscript`, which ships with Mathematica.

```bash
wolframscript -file tests/run.wls              # 7 checks, PASS/FAIL per line
wolframscript -file scripts/sweep.wls          # writes results/sweep.csv and .png
wolframscript -file notebooks/build_notebook.wls   # regenerates Household.nb
```

The test runner prints one line per check and exits with status 1 if any fails, so
Claude (or a script) can act on the exit code.

## Opening the notebook

Open `notebooks/Household.nb` in Mathematica (double-click it, or
`open notebooks/Household.nb` on a Mac) and evaluate the notebook
(Evaluation > Evaluate Notebook). The first input cell sets the directory to the
notebook's folder, clears the package's symbols and loads `../src/Household.wl`.
After you or Claude edit the package, rerun that cell to pick up the change.

## VS Code setup

Install the **Wolfram Language** extension by Wolfram Research
(`wolframresearch.wolfram`). It gives syntax highlighting and a language server for
`.wl`, `.wls` and `.wlt` files. Point it at your kernel in `settings.json`, for a
default Mac install:

```json
"wolfram.systemKernel": "/Applications/Mathematica.app/Contents/MacOS/WolframKernel"
```

The extension's own notebook format is `.vsnb`; `.nb` notebooks open in Mathematica.
